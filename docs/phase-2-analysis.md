The approved V1.1 stylesheet and brand tokens are byte-for-byte unchanged. No packages, upload endpoints, paid APIs, database, authentication or server image processing were added. No commit, push or deployment was performed.

## Definitions

Let `a` be the alpha byte (0–255), `A` the sampled cell's pixel area, and `w = a × A`. For an all-pixel analysis, `A = 1`. An opacity-weighted result is computed over the visible color contribution, without adding a background.

- **Average RGB:** `round(Σ(w × channel) / Σw)`, independently for each encoded sRGB byte channel. This is an arithmetic channel average, not an average of linear light energy. Integer sums are exactly representable within the app's 40-million-pixel limit.
- **Relative luminance:** normalize each sRGB channel to [0,1]; divide by 12.92 below/equal to 0.04045, otherwise use `((c + 0.055) / 1.055)^2.4`. Then `L = 0.2126 R + 0.7152 G + 0.0722 B`. This follows the [W3C sRGB relative luminance definition](https://www.w3.org/TR/WCAG21/relative-luminance.html). It is dimensionless, not perceived brightness or a physical luminance reading in cd/m².
- **Mean luminance:** `Σ(w × L) / Σw`.
- **Tonal spread:** `sqrt(Σ(w × (L − mean)^2) / Σw)`, calculated using weighted Welford updates. This is standard weighted population standard deviation, chosen to describe tonal variation. It is not a universal image-contrast score, normalized coefficient of variation, Michelson contrast or text accessibility ratio.
- **Range:** min/max among positive-alpha analyzed pixels. These are source extrema only for the all-pixel mode; a sample can miss them.
- **Histogram:** 32 equal-width luminance bins, half-open except the last includes 1. Each bin's share is its effective weight divided by total effective weight. Empty bins are zero. Bar heights are normalized to the largest bin for presentation; labels report actual shares.
- **Tonal bands:** shadows below 0.2, midtones from 0.2 to below 0.7, highlights from 0.7 through 1. These are product-defined cutoffs, not a standard exposure classification.
- **Opacity-weighted coverage:** `Σ(a × A) / (255 × ΣA)`. It describes average alpha across image area. For example, an image with every pixel at alpha 128 has roughly 50.2% coverage although every pixel is nontransparent.
- **Dominant colors:** up to six weighted k-means families in encoded RGB space, using 5-bit bucket means. Their HEX values are rounded centroids and their shares use the same weights as the other metrics. They are approximate representations, not perceptually uniform clustering or semantic color predictions. RGB components within a bucket span at most seven byte levels before clustering. Equal displayed HEX values combine shares.

Rounded shares may total 99.9% or 100.1%; the underlying normalized shares total 1 within floating-point tolerance.

## Sampling and reproducibility

Every decoded pixel is analyzed when the image has at most 262,144 pixels, including wide/small images such as 600×400. For larger images, an aspect-aware grid contains at most 262,144 cells. Integer cell boundaries partition the complete image; one native integer coordinate is selected uniformly within each cell using a seeded generator. The seed depends on dimensions, not file name or current time. A fixed decoded bitmap yields repeatable positions and results. Native 512×512 tiles are read only where sample points occur, on an explicitly sRGB OffscreenCanvas with smoothing disabled and no scaling.

Cell-area weighting avoids oversampling smaller cells. It does not guarantee exact recovery of rare colors or eliminate sample error. Alpha-weighted means are ratio estimates for sampled images; exceptionally sparse visible pixels can make them unstable or absent. No confidence score or universal error bound is invented. The tests below demonstrate errors within specific tolerances for their fixtures, not for every possible image.

The tile reader, worker and UI cleanup close ImageBitmaps, reset canvases, clear sample buffers and discard stale generations. Completed buffers are cleared before the final response is posted. Sampling and calculations remain local. The [OffscreenCanvas API](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas) supports this separation of canvas work from the main UI thread.

## Image DNA

The Overview's Image DNA paragraph uses a deterministic template populated from actual dimensions, detected format, analysis basis, average RGB/HEX, largest measured RGB family/share, mean luminance, tonal standard deviation and opacity-weighted coverage. It generates no moods, scene descriptions, exposure diagnoses or AI interpretations. Image DNA is a readable statistical summary; different images can have the same summary.

## Performance and approximation limits

- Pixel calculations are capped at 262,144 points; color buckets are capped at 32,768; k-means has at most six centers and 24 rounds. Uniform images converge early.
- A tile canvas and its readback buffer each hold at most 1 MiB of RGBA. The sampled RGBA buffer is at most 1 MiB; coordinate/area arrays add at most 3 MiB. Group lists, palette buckets and browser-managed decoded images consume additional memory.
- On this machine, a full Chrome regression run measured roughly 469 ms from Analyze click to result for a 2048² checkerboard, 377 ms for a 4096×1024 ramp, and 322 ms for a 1024² uniform image. These include browser automation/rendering overhead and concurrent tests, and are observations rather than device-independent performance guarantees.
- Native tile work can read much of a large source even though the retained/statistically analyzed sample is capped. Full-image decode memory is still needed; the existing 40-million-pixel limit is checked after decode. Browser image-dimension limits also apply. Analysis has a 20-second worker timeout.
- Decoded canvas values are 8-bit sRGB. Profiles, higher-bit-depth sources, browser color management and very low-alpha premultiplication/unpremultiplication can change rounded values. Tests use profile-free 8-bit fixtures.
- Animated images are measured at a decoded frame. Results describe that bitmap rather than the complete animation. Rare source colors/extrema may be missed by sampling; color families are approximate in both modes.
- Worker native sampling requires ImageBitmap and OffscreenCanvas support. Unsupported browsers receive an explanatory error. Browser testing used installed Chrome and viewport emulation, not physical mobile devices or other engines.
