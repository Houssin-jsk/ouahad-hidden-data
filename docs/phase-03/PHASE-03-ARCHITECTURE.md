### Code and boundaries

- `src/cloud-vision/contract.ts`: versioned available/unavailable contract, provider/model identity, concise description, <=4 short observations and limitations, classified errors and bounded processing/usage metadata. No confidence percentages or verified numerical fields. External JSON is shape/length validated; truth is not guaranteed by syntax.
- `client.ts` re-encodes oriented visible pixels as JPEG on white, with <=1024 side and <=768 KiB. No filename/EXIF/GPS/original metadata, URL-fetch service or permanent image upload. The server additionally walks the JPEG container, checks signatures/frame dimensions/truncation/scan boundaries, rejects unsupported MIME and removes all APP/COM segments. Container validation is not a second full JPEG entropy decode; the provider can reject corrupt payloads safely.
- `server/providers/{gemini,nvidia,cloudflare}.ts` own request and response shapes, exact model identity, constraints and eligibility. Native fetch only; no AI framework or new dependency. `http.ts` bounds streamed provider JSON to 32 KiB, disables redirects/caching, applies 12-second provider timeout and safe classified errors. Cloudflare documented error codes distinguish capacity, free quota, billing-only models and missing models/licenses.
- `router.ts` fixes Gemini → NVIDIA → Cloudflare, <=3 attempts, one provider at a time, immediate success return. Quota/rate failures write shared cooldowns. Only provider Retry-After/RetryInfo or documented Cloudflare 3036 midnight UTC reset schedules automatic availability. Unknown reset, bad credentials, unavailable models and billing requirements suspend until operator review. No background polling. Transient outages/timeouts can use an eligible fallback. Safety refusal, invalid input/output and cancellation stop further vendor disclosure.
- `handler.ts` checks POST, exact configured origin, fetch-site context, explicit consent/eligibility revision headers and owner-issued high-entropy invitation before reading the image or contacting inference. Streaming byte limit applies even without Content-Length. Browser action timeout is 50 seconds; server processing deadline is 45 seconds; Next function maximum is 60 seconds. No raw provider error, secret, prompt or pixels enters application logs/errors. Buffered bytes are cleared best-effort, not a guarantee of runtime memory erasure. The route imports `server-only`; release checks reject provider-secret references in browser chunks.
- `components/cloud-observations.tsx` replaces the companion import under Overview. Four tabs, branding, local metadata/GPS controls and six-second local presentation stay intact. Consent/access stay in component memory, with no localStorage/cookies. Replacement/unmount abort active work, invalidate generations and reset consent/access; cancel rejects late results. No AI/status/provider requests occur during ordinary local analytics or simply opening the disclosure.

### Restricted abuse protection

No anonymous inference is exposed. Offline owner-issued 256-bit codes are hashed with SHA-256 for lookup in server-only `CLOUD_AI_INVITES`; owner-vetted MA professional participants expire within seven days. The supplied helper generates one-day invitations. No arbitrary IP or identity header is trusted. Adult/MA/professional/non-sensitive image attestation and consent are both required. Codes are capabilities, can be shared or stolen, and are not full accounts or verified geolocation. Owner distribution/vetting is part of the restricted access boundary; other regions and open consumer use need a separate eligibility design.

`SharedLedger` uses Cloudflare D1 REST with a **single atomic INSERT ... SELECT** for admission. Fixed bounds: **1 request per participant/minute, 3 per participant/UTC day, 10 actions globally/UTC day, 1 active request globally**, and <=3 provider attempts per admitted action. Invalid admitted attempts consume budget. D1 serialization prevents serverless read/write races. Leases expire after 120 seconds after crashes; normal completion releases them. The lease exceeds the 60-second function lifetime; provider-side work may continue after transport cancellation, outside application control. No process-local quota/concurrency/cooldown state is authoritative.

The ledger holds only random job ID, access-code hash, timestamps, lease/released state and provider cooldown. Requests prune job rows older than two days; if there is no further traffic, old rows remain until explicit cleanup. D1 backups can retain this minimal ledger data. No image, prompt, user IP or generated description is stored. Exhausted shared-store quota, unavailable storage, missing schema, or bad D1 credentials fails closed. Valid-code abuse could exhaust D1's free request allowance and deny service, but may never justify upgrading to paid storage. The storage account must first be verified Workers Free; no resource was provisioned.
